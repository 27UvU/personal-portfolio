基础知识

数据库核心概念

数据库是长期存储在计算机内、有组织的、可共享的数据集合。关系型数据库使用表格来组织数据，是目前最常用的数据库类型。

关系型数据库

关系型数据库基于关系模型，数据以行和列的形式存储在表中，表与表之间可以建立关系。

  • 表（Table）：数据的逻辑组织单位
  • 行（Row）：一条记录
  • 列（Column）：字段/属性
  • 主键（Primary Key）：唯一标识每条记录
  • 外键（Foreign Key）：建立表之间的关系

SQL 语句

SQL（Structured Query Language）是操作关系型数据库的标准语言，包括数据查询、定义、操纵和控制四大类。

索引

索引是帮助数据库高效获取数据的数据结构。常见的索引类型包括 B-Tree 索引、哈希索引等。合理使用索引可以大幅提升查询性能。

事务 ACID

  • 原子性（Atomicity）：事务是不可分割的最小工作单元
  • 一致性（Consistency）：事务执行前后数据库处于一致状态
  • 隔离性（Isolation）：并发事务之间相互隔离
  • 持久性（Durability）：事务一旦提交，对数据的修改是永久的

Normalization（规范化）

数据库规范化是通过分解表来消除数据冗余和更新异常的过程。常见范式包括 1NF、2NF、3NF 和 BCNF。

图文教程

步骤一：CREATE TABLE

CREATE TABLE users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE orders (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL,
    amount DECIMAL(10, 2) NOT NULL,
    status ENUM('pending', 'paid', 'shipped') DEFAULT 'pending',
    FOREIGN KEY (user_id) REFERENCES users(id)
);

步骤二：SELECT 查询

-- 基本查询
SELECT * FROM users WHERE age > 18;

-- 聚合查询
SELECT status, COUNT(*) as count, AVG(amount) as avg_amount
FROM orders
GROUP BY status
HAVING count > 5;

-- 子查询
SELECT * FROM users
WHERE id IN (SELECT user_id FROM orders WHERE amount > 1000);

-- 分页查询
SELECT * FROM users
ORDER BY created_at DESC
LIMIT 10 OFFSET 20;

步骤三：JOIN 与索引创建

-- INNER JOIN
SELECT u.username, o.amount
FROM users u
INNER JOIN orders o ON u.id = o.user_id;

-- LEFT JOIN
SELECT u.username, COUNT(o.id) as order_count
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
GROUP BY u.id;

-- 创建索引
CREATE INDEX idx_user_email ON users(email);
CREATE UNIQUE INDEX idx_username ON users(username);

-- 复合索引
CREATE INDEX idx_order_status_date ON orders(status, created_at);

知识检测

请完成以下题目，检验你的学习成果

1. DISTINCT 作用？
A. 排序结果
B. 消除重复行
C. 过滤空值
D. 限制返回行数
解析：DISTINCT 关键字用于返回唯一不同的值，消除查询结果中的重复行。
2. 隔离性解决什么问题？
A. 防止数据丢失
B. 防止并发事务相互干扰
C. 保证数据一致性
D. 提高查询性能
解析：隔离性（Isolation）确保并发执行的事务不会相互干扰，一个事务的中间状态对其他事务不可见。
3. 关于索引的错误说法？
A. 索引可以加速查询
B. 索引需要额外的存储空间
C. 索引越多越好不影响写入
D. 索引可以建立在多个列上
解析：索引虽然可以加速查询，但会增加写入操作的开销（需要维护索引结构），并占用额外存储空间。因此并非越多越好。

实践任务：SQL 查询优化

-- 优化前：全表扫描
SELECT * FROM orders
WHERE YEAR(created_at) = 2024
  AND status = 'paid';

-- 优化后：使用索引列和范围查询
SELECT id, user_id, amount, status
FROM orders
WHERE created_at >= '2024-01-01'
  AND created_at < '2025-01-01'
  AND status = 'paid';

-- 查看执行计划
EXPLAIN SELECT * FROM orders
WHERE user_id = 100 ORDER BY created_at DESC;

-- 优化 JOIN 查询
SELECT u.username, SUM(o.amount) as total
FROM users u
INNER JOIN orders o ON u.id = o.user_id
WHERE o.created_at >= '2024-01-01'
GROUP BY u.id
HAVING total > 10000
ORDER BY total DESC
LIMIT 10;
